# Voxel Vault release audit

Audit started 2026-09-18. Baseline checkpoint: `863fb58` (existing work preserved separately). Package 16.0.0, browser stamp 31, save schema `VERSION=2`, terrain generation 5/6. Dependency-free ES modules, bundled Three.js r160, one terrain worker, merged solid/water/glass chunk geometry, procedural atlas, Node HTTP/SSE multiplayer. `lingo-loop/` is an unrelated untracked project and is excluded.

## Implementation sequence and release gates

1. **Audit/instrument:** reproducible benchmarks, p95/heap/resource/save diagnostics, deterministic startup/realm/save browser smoke; repair stale browser checks.
2. **Reliability:** delayed-action lifecycle, startup/save errors, validated backups and recovery, debounced durable saves and compatibility fixture.
3. **Measured performance:** safe Auto preset, bounded shadow casters/light index, reuse models/scratch state, AI/entity budgets, streaming priority and resource soak.
4. **Controls/UX/progression:** input cleanup/remapping/accessibility, touch ergonomics, specific dismissible objectives, useful inventory/map improvements and fair encounter feedback. Preserve existing modes and saves.
5. **Ultimate release gate:** complete browser/unit/performance/soak/migration checks; report unavailable platforms honestly.
6. **Only then structures:** deterministic infrastructure → old outposts → representative small/medium/rare templates → measured realm/biome expansion.
7. **Playable visuals:** matched atmosphere/material captures and preset benchmarks before preview art.
8. **Icons:** source pipeline/models → actual PNGs/contact sheets → strict alpha/framing/size/uniqueness QA.
9. **Final release:** stamp once, full tests, deployment asset parity and final report.

Desktop budget: ordinary Medium p95 <20ms; simulated mobile Low p95 <34ms; large-world save main-thread work <8ms; bounded resource growth over a real 30-minute scripted run. Initial measurements already meet the sampled rendering targets; optimization claims require lower measured cost or improved stress behavior, not a capped-FPS claim.

Phase outcomes, commit hashes, changed files and remaining risks will be appended here as work lands. No release is declared complete while a gate is outstanding.

## Phase 1 — instrumentation and regression repair

Added bounded frame percentiles, long-task collection and development resource/save diagnostics; restored backpack discovery controls; isolated browser contexts and repaired assertions for current crafting requirements, retired resources, inventory search and touch geometry. Preview capture no longer overwrites shipped images unless explicitly requested. Added portable benchmark and complete browser runners plus a pre-upgrade fixture.

Validation: 189/189 unit tests. Full browser run: 17/18 passed; the hunting suite failed once in a random-seed firing lane, passed in isolation, and its fixture was changed to clear the shot corridor. Final targeted result is recorded alongside the full run. No rendering optimization claimed in this phase. Baseline metrics remain the comparison reference. Safari automation remains disabled; Firefox is unavailable. Next: lifecycle-safe delayed actions and durable, recoverable saving.

## Phase 2a — recovery and lifecycle safety

Added recovery rotation, corrupt/unsupported-save write protection, explicit replacement backups, versioned JSON export/import, truthful save status, stage-specific startup errors and refundable cancellation of armed charges across pause/reload/world changes. The v2 key and terrain generation versions remain unchanged. Validated the real pre-upgrade fixture, all realm edits and explicit air.

Validation: 196/196 full unit tests before the final lifecycle integration test; 6/6 focused explosion/recovery tests including that new test; real browser gameplay/save-reload check passed with no runtime errors or failed assets. This step does not claim faster saving: synchronous fallback snapshots remain, and the next step replaces browser autosave serialization with worker-backed IndexedDB.

## Phase 2b — worker-backed durable saving

Browser saves now debounce small metadata snapshots and transfer changed blocks in batches of at most 500 to a dedicated worker. IndexedDB atomically commits the world plus two recovery snapshots. The legacy localStorage world is retained. Explicit full snapshots are used for realm/solo-mode transitions and export; ordinary saves do not rebuild the edit array. The original synchronous implementation remains a storage-unavailable fallback and for headless unit fixtures. Failed writes retain dirty changes for retry.

Measured browser baseline: 100k edits 8.1 ms synchronous. New incremental save requests: 0.1–0.2 ms on this Mac, with full snapshot work off the gameplay thread. See phase2-persistence.json. Real migration/reload verified inventory, containers, crops, explicit air and distinct saved realm snapshots. 198/198 unit tests passed before two additional durable-storage tests (2/2 passed). Full browser run: 18/19 passed; multiplayer's state comparison required the explicit snapshot API and its targeted rerun passed. The final realm snapshot regression also passed. No physical-phone result or 30-minute soak is claimed.

Latest user steering prioritizes the structure/biome overhaul next, after this stable persistence checkpoint. Existing terrain versions will remain supported; new generation will have a separate version.

## Performance and responsive UI release checkpoint

Fresh settings now use Auto: Low on touch/memory-limited devices, Medium on typical desktops. Bounded frame samples and hysteresis adapt the preset; per-preset DPR caps remain. Shadows use a tighter moving camera, nearby terrain casters and 15/30 Hz updates. Shared immutable geometry, per-model materials and capped mob/projectile pools reduce rebuild churn. Hand bindings and crosshair references are cached. Hostile LOS/path work has per-frame limits, with fair rotating scheduling; crowded projectile checks use a spatial broad phase. Same-seed durable imports now explicitly preserve a replacement backup. High-only realm particles/planet/nearby anchor lighting were re-enabled with bounded costs.

Measured camp scene: Medium draw calls 139 baseline → 79, High 168 → 137; p95 remains 16.7–16.8 ms at the display cap. Auto touch, 390×844 DPR2 with 4× CPU throttling: Low at DPR1, p95 16.7 ms. These are sampled browser results, not physical hardware or a claim that every scenario is 60 FPS. See reports/phase3-frames.json. The pre-UI browser run passed 20/21 entry points (reports/phase3-browser.json). One random terrain fixture obstructed the mining ray; its firing lane is now explicitly cleared, and the full subsequent run includes that regression. The first resource soak stopped on an overly strict eight-model fixture bound when a natural ninth animal spawned; no leak was established. A corrected 30-minute run is in progress; it is not yet release evidence.

User steering now prioritizes publishing the controls/UI fixes to GitHub Pages. Firecrackers can be used directly with H, a hotbar click/number key, a backpack click or the touch boost button without switching gear. Glider deployment immediately provides forward flight and arrests a steep fall; steering follows facing on the next simulation step while boost speed decays smoothly. Inventory bindings preserve the dialog, grids, unchanged item nodes/icons, focus and scroll; counts, recipe dependencies, armor slots, chest stacks, furnace rows, enchant rows, hotbar selection and status timers update individually. Zero-count stacks keep their place until reopening, avoiding a grid shuffle beneath the cursor.

Validation so far: 217/217 unit tests. A dedicated browser regression verifies DOM identity, focus/scroll preservation, every affected item screen, quick controls and stable effect timers. Full post-change browser checks and final stamped/deployed verification are recorded separately. Unwired progression work is intentionally excluded from this release; the later original progression, probabilistic enchanting, icon overhaul, expanded ecology and newly requested potion/fishing/trading/travel features remain pending. Existing farming and effect meals remain functional.
