Audit started 2026-09-18. Baseline checkpoint: `863fb58` (existing work preserved separately). Package 16.0.0, browser stamp 31, save schema `VERSION=2`, terrain generation 5/6. Dependency-free ES modules, bundled Three.js r160, one terrain worker, merged solid/water/glass chunk geometry, procedural atlas, Node HTTP/SSE multiplayer. `lingo-loop/` is an unrelated untracked project and is excluded.

## Implementation sequence and release gates

1. **Audit/instrument:** reproducible benchmarks, p95/heap/resource/save diagnostics, deterministic startup/realm/save browser smoke; repair stale browser checks.
2. **Reliability:** delayed-action lifecycle, startup/save errors, validated backups and recovery, debounced durable saves and compatibility fixture.
3. **Measured performance:** safe Auto preset, bounded shadow casters/light index, reuse models/scratch state, AI/entity budgets, streaming priority and resource soak.
4. **Controls/UX/progression:** input cleanup/remapping/accessibility, touch ergonomics, specific dismissible objectives, useful inventory/map improvements and fair encounter feedback. Preserve existing modes and saves.
5. **Ultimate release gate:** complete browser/unit/performance/soak/migration checks; report unavailable platforms honestly.
6. **Only then structures:** deterministic infrastructure → old outposts → representative small/medium/rare templates → measured realm/biome expansion.
7. **Playable visuals:** matched atmosphere/material captures and preset benchmarks before preview art.
8. **Icons:** source pipeline/models → actual PNGs/contact sheets → strict alpha/framing/size/uniqueness QA.
9. **Final release:** stamp once, full tests, deployment asset parity and final report.

Desktop budget: ordinary Medium p95 <20ms; simulated mobile Low p95 <34ms; large-world save main-thread work <8ms; bounded resource growth over a real 30-minute scripted run. Initial measurements already meet the sampled rendering targets; optimization claims require lower measured cost or improved stress behavior, not a capped-FPS claim.

Phase outcomes, commit hashes, changed files and remaining risks will be appended here as work lands. No release is declared complete while a gate is outstanding.

## Phase 2a — recovery and lifecycle safety

Added recovery rotation, corrupt/unsupported-save write protection, explicit replacement backups, versioned JSON export/import, truthful save status, stage-specific startup errors and refundable cancellation of armed charges across pause/reload/world changes. The v2 key and terrain generation versions remain unchanged. Validated the real pre-upgrade fixture, all realm edits and explicit air.

Validation: 196/196 full unit tests before the final lifecycle integration test; 6/6 focused explosion/recovery tests including that new test; real browser gameplay/save-reload check passed with no runtime errors or failed assets. This step does not claim faster saving: synchronous fallback snapshots remain, and the next step replaces browser autosave serialization with worker-backed IndexedDB.

## Phase 2b — worker-backed durable saving

Browser saves now debounce small metadata snapshots and transfer changed blocks in batches of at most 500 to a dedicated worker. IndexedDB atomically commits the world plus two recovery snapshots. The legacy localStorage world is retained. Explicit full snapshots are used for realm/solo-mode transitions and export; ordinary saves do not rebuild the edit array. The original synchronous implementation remains a storage-unavailable fallback and for headless unit fixtures. Failed writes retain dirty changes for retry.

Measured browser baseline: 100k edits 8.1 ms synchronous. New incremental save requests: 0.1–0.2 ms on this Mac, with full snapshot work off the gameplay thread. See phase2-persistence.json. Real migration/reload verified inventory, containers, crops, explicit air and distinct saved realm snapshots. 198/198 unit tests passed before two additional durable-storage tests (2/2 passed). Full browser run: 18/19 passed; multiplayer's state comparison required the explicit snapshot API and its targeted rerun passed. The final realm snapshot regression also passed. No physical-phone result or 30-minute soak is claimed.

Latest user steering prioritizes the structure/biome overhaul next, after this stable persistence checkpoint. Existing terrain versions will remain supported; new generation will have a separate version.

## Brewing and infusion checkpoint

Brewing extends the existing recipes, voxel atlas, food effects and inventory bindings. Twelve families have Normal, Strong and Extended recipes (36 bottles), reusable water flasks and a placeable station. Ingredient checks use obtainable canonical resources; rejected crafts/drinks spend nothing. Effects are capped, strongest versions replace weaker ones, one 3-second cooldown covers bottles, and saved timers pause with gameplay. Underwater breath is visible and restores on surfacing. New additive fields preserve the v2 save key and all existing geography. Bottle models are rendered at 2× with projected-camera framing; the 36-bottle contact sheet was visually reviewed at full and 36px size.

Enchanting adds five craftable altars, three XP investments, displayed probabilities, five package tiers and 23 implemented effects. Individual levels cap at III; conflicts and equipment tags are enforced. Existing aura becomes the displayed Vault XP balance. Valuable natural ores, hostile kills and first discoveries reward XP; trivial block mining and passive animals no longer do. Legacy upgrades/saves remain available; a new infusion replaces a legacy upgrade. Infusions follow the existing equipment-type architecture (all copies of that equipment share the roll), disclosed in the interface.

Secure browser randomness chooses rolls. A compact journal atomically saves payment and outcome before reveal; reload replays a pending transaction once. The world identity prevents the journal being applied to a newly reset same-seed world. This protects ordinary reloads/interrupted writes, not deliberate tampering with an offline browser or restored backups. Multiplayer/parkour infusion is disabled; no server-authoritative enchanting is claimed. Durability, vitality, shield stability and additional effects requiring broader combat/item-instance architecture are not advertised as implemented enchantments.

Validation: 232/232 unit tests. 75,000 simulated rolls cover all 15 altar/offer probability curves, power budgets, conflicts and levels. Targeted real browser tests cover brewing, cooldowns, stable inventory/timer DOM, reload, altar interaction, explicit reroll acknowledgement, odds/result/codex and 320/390/1440 layouts with no runtime errors or failed assets. Full browser run is recorded in reports/potions-enchanting-browser.json when complete. The earlier v32 30-minute resource soak also completed successfully (reports/soak.json); it is evidence for the rendering/resource foundation, not a 30-minute potion test.

## Emberwell follow-up (release 35)

Starting point: deployed release 34 (`8ec64ad`), 249 passing Node tests. The requested large-biome system is already actual runtime generation: 18 surface families plus cave/deep-cave labels, and 16 seeded ruin families. This follow-up preserves those systems, adds Emberwell Remains, and re-renders the biome/ruin tour instead of replacing the landscape again.

Confirmed and fixed:

- Underground meshing repeated chunk preparation and column lookup for every voxel. The mesh sampler now prepares each horizontal column once, while retaining the full cave volume, neighbor halo, edit precedence, collision blocks and exact output geometry. No vertical clipping optimization was applied.
- Generated lanterns were absent from the light index: the first in-game Emberwell capture was nearly black despite visible lantern blocks. Generated structures now maintain a separate bounded spatial light index. The renderer combines nearby edited/generated sources into the same four existing lights. Explicit player air edits suppress removed lamps, and pruning removes distant entries.
- Firecracker sparks were small, dim and concentrated in three narrow bursts. A four-stage volley now uses larger bright particles, broader spread and a final gold ring, with a fuller original synthesized sound. The same instanced pool enforces its quality-dependent cap; repeated activation cannot grow the delayed burst queue without bound. Instant unequipped use, payment, cooldown, stun and glider boost remain intact.

New terrain version 9 adds naturally embedded magma cave ruins with two chambers, pillars, dry crossings, sunken lava, visible spike traps, a breakable cache-room wall, seeded supplies and persistent defenders. Surface generation still uses the version-eight climate and tree families. Versions 5–8 retain their generated blocks; no save key/schema reset and no automatic conversion of an old world. Without a historical visited-chunk ledger, claiming safe automatic insertion into unexplored old terrain would be misleading. New magma structures therefore require a new world. Generated blocks stay out of `edits`; explicit air and player builds win.

Added 25 creature variants, without the four rejected guardian types: Horse, Stag, Gold Watermelon Stag, Wolf, Wildcat, Bear, Gorilla, Slime; Spirit Golem/Wolf/Bear/Stag/Gorilla; Cave Golem; Draugr Zombie/Skeleton/Huntress/Warper/Reaver; Frost Golem/Zombie/Skeleton/Wraith; Magma Golem; Crone. Existing Pig/Cow/Sheep/Deer/Draugr Knight/Stalker and the storyline guardian remain. Data-driven families use distinct quadruped, antler, ape, stone, slime, archer, hooded and heavy-weapon silhouettes. Ranged enemies shoot actual bolts and reposition, predators lunge, heavy creatures wind up, slime advances in hops, and warpers use bounded collision/line-of-sight-checked steps. Spawn caps and distance/AI budgets are retained. New animals persist with the existing animal save data. This does not add horse riding or promise every species at every location.

Repeatable Node benchmark: `node scripts/cave-benchmark.mjs [repository-path]`, seed 7821, terrain 8, 25 underground chunks, one warmup plus three measured passes (75 samples per realm). Before/after artifacts in `reports/emberwell/cave-before.json` and `cave-after.json`: Overworld median 9.53 → 7.02 ms, p95 12.29 → 9.63 ms, total 734.12 → 536.85 ms. Every realm's geometry SHA-256 and byte count match exactly. These are local CPU meshing measurements, not universal FPS guarantees or a physical-phone benchmark.

Added tests cover cave siting, legacy exclusion, chunk-order invariance, pruning/regeneration, explicit air, one-time cache collection, defender persistence, distant ±1,000,000 coordinates, valid loot/model definitions, spawn-family coverage, real ranged attacks, safe warps, passive save/load, generated lamp removal, and particle pooling.
